## Правила редактирования прогресса (safe-refactor)
- **Нельзя писать прогресс** в будущую дату, вне периода действия цели, и — **новое** — в
  день/неделю/месяц, который закрылся более **24 часов** назад. Такие периоды показываются
  **read-only** (без степпера/галочки). Bulk-кнопки («Выполнить всё»/«Очистить») работают
  только по записываемым целям. Логика: `canLogOn` / `isPeriodEditable` в `core/logic`.
- **Оптимистичное логирование** переписано на кэш React Query (cancel→snapshot→patch→rollback
  при ошибке→invalidate). При неудачном сохранении показывается баннер и откат.
- **Сохранение горизонта атомарно** (RPC `save_horizon`) — либо всё, либо ничего.
- **Ошибка геймификации не роняет** основное сохранение лога/целей.

## Известные нюансы
- Кэш браузера может держать старый бандл → `Cmd+Shift+R` после деплоя.
- **Прокси `/supabase-api` работает только на задеплоенном вебе** (нужен `vercel.json` rewrite).
  В локальном dev-режиме клиент ходит в Supabase напрямую — это норм.
- Геймификация считается, но UI («Прогресс») удалён — статы нигде не видны.
- 24-часовой лаг правок enforce-ится **на клиенте** (read-only). На сервере триггер проверяет
  только принадлежность лога активному периоду цели (не 24ч — чтобы не ловить TZ-расхождения).
