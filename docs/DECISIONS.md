# DECISIONS — принятые решения и почему

## Продукт / модель (ТЕКУЩАЯ — календарь)
- **Календарная модель вместо «сессий».** Ушли от 4-недельной «сессии» (отсчёт от создания) к
  жёсткой привязке к календарю: день/неделя/месяц как в Напоминаниях/Здоровье. **Неделя — с
  понедельника.** Сверху лента дней с числами, тап переключает горизонт, есть быстрый переход
  «Сегодня». (Крупный пивот лета 2026; данные при этом обнулялись — миграция 0003.)
- **Две сущности: Цели и Задачи** (дискриминатор `kind`).
  - **Цель** — долгая, ручные веса, «кол-во» 1–9, период только **навсегда** или **до даты**
    (нельзя «разово на период», нельзя задним числом). Экран «Цели», в шапке ＋ и шестерёнка-редактор.
  - **Задача** — простая галочка (тап = выполнено, тонет вниз), **всегда привязана к периоду**,
    `target=1`, веса авто-равные. Экран «Задачи». Как в Напоминаниях.
- **Кольца вложенные, доли 60/40 и 80/20** (не 50/50). Неделя = 60% дни + 40% недельные цели;
  Месяц = 80% недели + 20% месячные. Отсутствующая половина = 0 без перенормировки. **Формула —
  явное требование пользователя, не менять без спроса.**
- **Знаменатели колец — ДИНАМИЧЕСКИЕ.** Усредняем не по фиксированным 7 дням / 4 неделям, а только по
  тем, где ЕСТЬ активные цели. Пример: 4 активных дня → идеальный день даёт 60%/4 = 15% (проверено
  численно). Причина: пользователь не хотел, чтобы кольцо «недобирало» из-за дней без целей.
- **«Кол-во» вместо «цель», выпадающий список 1–9, по умолчанию 1.** Старые значения >9 клампятся к 1.
- **Веса — % внутри горизонта, сумма 100%.** У целей — ручной ввод + кнопка «Поровну»; при добавлении
  новой строки веса авто-выравниваются. У задач — всегда авто-равные. Удаление
  перераспределяет вес между оставшимися.
- **Выполненные тонут вниз** (стабильная сортировка) — и цели, и задачи.
- **Редактор `HorizonEditor` показывает только элементы, активные в текущем периоде** (`goalsForScope`
  для выбранной даты) — иначе при добавлении всплывали элементы соседних дней (фикс `c2791ba`).
- **Перевыполнение запрещено** (кап на target/остаток).
- **Сущность «Прогресс»/ачивки — временно убрана из UI.** Движок геймификации считается, но вкладки
  нет; вернёмся к ачивкам позже.

## Технические
- **⚡️ RU Cloudflare throttling → Vercel same-origin прокси.** Supabase за Cloudflare, росс.
  провайдеры троттлят (~16КБ/соединение с 2025-06-09) → «висит/вчера работало». НЕ баг кода. Решение:
  на вебе клиент ходит через `${origin}/supabase-api/*`, а `vercel.json` rewrite'ит это на Supabase
  (Vercel не за Cloudflare). См. `resolveClientUrl` в `supabase.ts`. **Диагностировать такое как сеть,
  а не как регрессию.** (память `novigo-ru-cloudflare-throttling`.)
- **Auth: email+пароль БЕЗ подтверждения email.** Supabase не даёт править email-шаблоны без своего
  SMTP → OTP не кладём. «Confirm email» выключен.
- **supabase-js: обязателен no-op `lock`** (`(_n,_t,fn)=>fn()`). Дефолтный `navigator.locks` даёт
  дедлок на вебе (логин-POST 200, но промис висит — были «вечные скелетоны»). Плюс `fetchWithTimeout`
  (AbortController, 8с) и `storageKey: 'sb-novigo-auth'`.
- **Web output = "single" (SPA).** `static` (SSR) падал на `window`. `vercel.json` даёт SPA-rewrites.
- **typedRoutes выключен** — чтобы строковые пути не ловили типовые ошибки.
- **Дизайн: чистый минимал.** Нейтральные степперы, цвет только в точке и баре; палитра горизонтов —
  прохладная триада индиго/голубой/фиолет. Пользователь чувствителен к визуалу — причёсывать.

## Отменённое / удалённое (не возвращать без спроса)
- **Админ-режим** (`admin`/`1111`, скруббер дней) — удалён целиком.
- **«Сессии целей»** (`goal_sessions`, отсчёт от создания, «одна сессия за раз», онбординг про
  сессию) — удалены.
- **Вкладка «Прогресс»** — удалена.
- **Стрелки-переключатели дат отдельной строкой** — пользователь отменил (оставили как было).
