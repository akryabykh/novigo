# Novigo

Кросс-платформенный трекер целей: вы создаёте **программу** на период (неделя / 2 недели / месяц), разбиваете её на **задачи** с весами (в сумме 100%), каждый день отмечаете прогресс — а приложение считает взвешенный прогресс, серии (streak), XP и уровни.

Один кодбейс на **web / iOS / Android** (Expo + react-native-web). Сейчас собран и проверен веб; мобильные сборки — через EAS позже, код к этому готов.

## Стек

- **Expo SDK 56** + React Native + **Expo Router** (web через react-native-web)
- **NativeWind** (Tailwind для RN) + дизайн-токены в одном месте (`src/ui/theme.ts`)
- **Supabase** — Postgres + Auth + RLS
- **zod** (валидация) + **@tanstack/react-query** (серверное состояние)
- Бизнес-логика (прогресс / стрики / XP) — чистые функции в `src/core/logic`

## Архитектура

```
src/
  app/                 # экраны (Expo Router): (auth) и (app)/(tabs)
  core/
    domain/            # типы сущностей
    logic/             # ЧИСТАЯ бизнес-логика (прогресс, стрики, XP) — юнит-тестируемо
    data/              # Supabase-клиент + репозитории (CRUD) + мапперы
    validation/        # zod-схемы
  ui/                  # дизайн-токены (theme.ts) + компоненты (NativeWind)
  features/            # auth, programs, gamification, profile (хуки react-query, движок геймификации)
supabase/migrations/   # 0001_init.sql — схема + RLS
```

UI один на все платформы и тонкий: расчёты живут в `core/logic`, экраны их только вызывают.

## Setup

### 1. Зависимости
```bash
npm install
```

### 2. Проект Supabase
1. Создайте проект на https://supabase.com (отдельный, изолированный).
2. **SQL Editor** → вставьте и выполните `supabase/migrations/0001_init.sql`.
3. **Authentication → Providers → Email**: включите вход по email+паролю и подтверждение email (OTP-код).
4. (Опц.) **Authentication → URL Configuration** добавьте URL вашего веб-деплоя в Redirect URLs — для ссылок сброса пароля.

### 3. Переменные окружения
```bash
cp .env.example .env
```
Заполните из **Project Settings → API**:
```
EXPO_PUBLIC_SUPABASE_URL=https://<ref>.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=<anon public key>
```
> Пока ключи — заглушки, приложение показывает экран настройки вместо входа.

### 4. Запуск (web)
```bash
npx expo start --web
```

## Деплой веба на Vercel

Сборка — статический SPA (`web.output: "single"` в `app.json`).

1. До публикации офлайн-клиента выполните `supabase/migrations/0008_offline_sync.sql`, перед выпуском переноса задач — `supabase/migrations/0009_task_move.sql`, перед выпуском статистики и медалей — `supabase/migrations/0010_medal_periods.sql`, а **перед выпуском закрытия периода в полночь** — `supabase/migrations/0011_close_periods_at_midnight.sql` в Supabase SQL Editor. Если `0011` уже выполнена, теперь выполните `supabase/migrations/0012_restore_task_periods.sql` целиком в новой вкладке; в результате `tasks_outside_one_period` должно быть `0`. Старые миграции не запускайте повторно и не переписывайте.
2. `node scripts/build-web.mjs` → артефакт в `dist/`, включая manifest и service worker.
3. На Vercel: Build Command берётся из `vercel.json` (`node scripts/build-web.mjs`), Output Directory — `dist`. Если в настройках проекта задано собственное значение Build Command, обновите его вручную.
4. Добавьте переменные `EXPO_PUBLIC_SUPABASE_URL` и `EXPO_PUBLIC_SUPABASE_ANON_KEY` в Project → Settings → Environment Variables.
5. SPA-роутинг: все пути отдаются на `index.html`.

На iPhone откройте сайт в Safari с интернетом, войдите в аккаунт и дождитесь загрузки целей. Через «Поделиться» → «На экран Домой» добавьте Novigo. Откройте установленную иконку с интернетом хотя бы один раз, затем проверьте режим полёта: добавьте тестовую цель/задачу, закройте приложение, откройте снова и верните сеть. Баннер показывает число ожидающих правок и конфликт между устройствами. Фоновая отправка при полностью закрытом Safari не гарантируется: очередь отправляется при следующем открытии или возвращении связи.

Задача относится только к выбранному дню, неделе или месяцу и не появляется автоматически в следующем периоде. Перенос через меню действий назначает её на другой период. Период закрывается в местную полночь после его последнего дня. В закрытом периоде меню задачи позволяет только удалить её или создать отдельную копию в текущем открытом периоде того же типа. После ошибочного применения `0011` выполните корректирующую миграцию `supabase/migrations/0012_restore_task_periods.sql` в Supabase SQL Editor: она ограничивает задачи их исходным календарным периодом.

### Статистика и медали

Статистика и медали находятся внутри профиля, сразу после карточки пользователя; отдельной вкладки и переключателя больше нет. До выполнения миграции `0010` статистика на сервере недоступна. При изменении правила закрытия периода порядок выпуска тот же: сначала SQL `0011` в Supabase, затем обновлённый веб-код.

Учёт начинается с даты выполнения миграции: старые удалённые задачи восстановить нельзя. Дневной период учитывается с этого дня; первая неделя или месяц учитываются только если начались не раньше даты миграции. Пустой период прерывает серию. День, неделя и месяц считают **только задачи собственного типа**. Результат фиксируется после окончания периода в местную полночь, без окна исправлений. Когда приложение было закрыто, используется последний сохранённый часовой пояс устройства. После подключения сначала отправляется офлайн-очередь, затем завершаются пропущенные периоды. Личный рекорд не снижается; бронза — 1–49, серебро — 50–99, золото — 100+.

### Счётчик

В нижней панели откройте «Приложения» → «Счётчик». Название счётчика можно изменить; оно синхронизируется между устройствами. Кнопки `+1` и `−1` изменяют значение (ниже нуля счётчик не опускается); результат можно сохранить в историю или сбросить на ноль. Значение и история доступны офлайн и синхронизируются между устройствами одного аккаунта после восстановления сети. Перед выпуском обновлённого кода запустите целиком `supabase/migrations/0013_counter_sync.sql` в Supabase SQL Editor (ожидается `Success. No rows returned`). Потом закоммитьте и отправьте изменения через GitHub Desktop. Старый счётчик с устройства импортируется при первом подключении; если на нескольких устройствах были разные локальные значения, они суммируются. Кнопки `+1`/`−1` складываются без потерь при одновременной работе; сброс и очистка истории применяются в порядке поступления на сервер. Если приложение было закрыто без сети, отправка продолжится при следующем открытии. До запуска SQL счётчик остаётся локальным, а раздел покажет ошибку синхронизации.


### Секундомер

В нижней панели откройте «Приложения» → «Секундомер». Выберите текущую задачу Novigo или введите своё название, затем нажмите «Начать работу». Можно поставить отсчёт на паузу, продолжить, завершить и сохранить сессию или сбросить без сохранения. Текущий отсчёт хранится на устройстве и восстанавливается после закрытия приложения; прошедшее время вычисляется по часам устройства. Завершённые сессии и их суммарное время доступны офлайн и синхронизируются между устройствами после восстановления сети. Активный отсчёт остаётся на том устройстве, где был начат.

Для названия счётчика и секундомера **сначала** выполните целиком `supabase/migrations/0014_counter_title_and_stopwatch.sql` в Supabase SQL Editor после `0013_counter_sync.sql` (ожидается `Success. No rows returned`), затем отправьте код через GitHub Desktop и дождитесь деплоя. До выполнения `0014` название и история секундомера не смогут синхронизироваться.

## Геймификация (правила)

- **Активный день** для стрика — дневной прогресс ≥ 80% (`STREAK_ACTIVE_THRESHOLD` в `src/ui/theme.ts`).
- **XP:** +10 за выполненную задачу, +5 за 100% дня, +100 за завершённую программу. Кривая уровней — `levelFromXp` в `core/logic`.
- XP/уровни/стрики **пересчитываются из данных** (идемпотентно) при каждом изменении — без двойного начисления.
